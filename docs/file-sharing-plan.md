# Paste 文件分享最小实施方案

本方案在现有文本分享上增加单文件分享，重点是访问控制、次数语义、文件生命周期和兼容性。保持 Next.js 单服务、SQLite 和本地卷，不引入对象存储、Redis、队列或新账号体系。实施参数按此版本采用以下默认值。

核对基线：2026-10-03，`dnslin/paste` 的 `7350235`。现有 `pastes.content` 必填，文本验证在 SQLite 事务内解密并扣次数；文件必须独立分支，不能直接套用文本读取逻辑。[表结构](https://github.com/dnslin/paste/blob/7350235794ec6e4a664aa35812ab5f83a5aff695/src/lib/db/schema.ts) · [文本读取实现](https://github.com/dnslin/paste/blob/7350235794ec6e4a664aa35812ab5f83a5aff695/src/lib/paste.ts)

## 一 先确认范围

v1 采用以下已确认实施边界。

- 仅已登录管理员上传文件，复用现有管理员会话；文本创建权限不变。匿名上传需要另评估滥用和容量，不能只开放按钮
- 一次一个文件，最多 10 MiB；过期默认 1 天、最长 7 天，不提供永久文件；次数沿用 1、3、5、10，接口接受 1–10
- 文件目录配额建议 1 GiB，至少保留 128 MiB 磁盘余量；短期下载凭证建议 15 分钟；清理每 5 分钟执行一次
- 过期或撤销后回收文件及其分享记录，不保留文件历史列表；次数耗尽时等待既有凭证到期。旧文本保留行为不变
- 任意附件作为不透明字节保存，仅供下载；不预览、不解析、不解压、不做缩略图，不支持多文件、混合文本、续传和文件替换
- 文件可能有害，不提供“已查毒”承诺；接收方自行判断是否打开。任意附件适用可信上传者的小站，不能等同于公开上传平台的防护水平

## 二 必须成立的规则

1. 打开页面、查看元数据、验证密码均不扣次数。点击下载并成功领取凭证才扣一次；表示一次下载授权，不表示用户成功保存一次
2. 凭证有效期内，同一凭证可重复请求完整文件，不重复扣次数。因此不能承诺“一次 HTTP 下载”或阻止转发、保存后传播
3. 次数耗尽只禁止领取新凭证，已领取凭证仍可使用。分享过期或管理员撤销，所有新的下载请求立即拒绝；已通过最后权限检查的响应允许完成
4. 有密码的文件，验证前不返回原文件名、大小、类型和存储路径；HTML、预取数据及 API 都遵守。密码不是文件加密密钥，服务端有能力解密
5. 文件只有完整落盘并提交数据库后才公开。数据库无文件字节，`public/`、静态资源路由、Nginx 均不能直接访问存储目录

## 三 数据和接口

只涉及三张业务表；已有密码失败记录表照常复用，不另建上传会话或任务表。

- `pastes`：增加 `kind`，默认 `text`，只允许 `text/file`；共享 ID、密码哈希、过期时间和剩余次数。为避免重建旧表，保留 `content NOT NULL`，文件固定写空字符串作为兼容占位；仅 `kind` 决定类型。创建校验沿用文本非空要求，并确保文件分享在同一事务内插入文件行；原文本字段只供文本分支使用
- `files`：`pasteId` 主键及外键、随机且唯一的 `storageKey`、清洗后文件名、实际字节数、加密版本、nonce、tag、`state=ready/deleting`。一份分享最多一条文件记录；发布后不可修改载荷
- `download_grants`：`tokenHash` 唯一主键、`pasteId` 外键、`createdAt/expiresAt`。按分享和到期时间索引；过期记录保留至分享删除，防止同一幂等键过期后再次扣费。文件最多领取 10 次，记录量有界

新增文件接口：

- `POST /api/files`：管理员 multipart 上传，返回现有形式的 `/{id}` 分享地址
- `POST /api/files/{id}/verify`：校验密码后返回文件元数据，不扣次数；无密码时也可调用
- `POST /api/files/{id}/claim`：接收 `password?` 和 `claimKey`，原子领取下载授权，返回有效期及剩余次数
- `GET /api/files/{id}/download`：通过 `Authorization: Bearer <claimKey>` 下载；显式实现 `HEAD` 为 405，避免框架自动执行 GET

现有 `GET /api/pastes/{id}` 对文件仅返回类型、密码状态和可公开的分享状态。旧 JSON 创建 API、文本 verify 响应、文本 URL 与扣次数方式不改；文本 verify 收到文件 ID 明确拒绝，不能当空文本读取。管理端保留旧文本查看能力，文件只展示元数据、撤销操作，不顺带开放管理员绕过限制下载。

### 领取和重试

浏览器首次点击下载时，用 Web Crypto 生成 32 字节随机 `claimKey`，按分享 ID 保存在 `sessionStorage`；它同时是幂等键和短期 bearer，密码不持久化。服务器严格校验编码长度，仅保存 SHA-256，绑定精确分享。凭证绝不进入 URL、访问日志或埋点。[随机数 API](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues)

先查已有凭证：若匹配分享且未过期、未撤销，原样返回，不要求重复密码，不检查剩余次数；已过期则拒绝，同一键不能创建另一份授权。新领取先校验密码和限流，在事务外确认文件可读且认证解密成功，再执行短的 `BEGIN IMMEDIATE` 事务：重查凭证、文件状态、过期时间、密码锁定和剩余次数，条件扣减一次并插入凭证，任一步失败全部回滚。事务内不做文件 I/O 或异步密码计算；凭证期限取“当前时间加 15 分钟”与分享过期时间的较早值。

响应丢失、连点、刷新均沿用原键重试。GET 不扣次数，不接受文件路径；凭证与分享不匹配一律拒绝。凭证过期后，如仍有次数，界面提示再领取会扣一次，由用户明确点击，不能后台自动换键。

## 四 上传 下载和清理

### 有界处理和加密

Node 运行时处理上传，先校验管理员会话、同源请求和速率，再接收文件。应用按实际读取字节限制请求体和文件大小，multipart 只允许一个文件、少量限定字段；缺失或伪造 `Content-Length` 不能绕过。不要先无限制 `formData()` 再检查大小。文件限制 10 MiB，请求总量建议 11 MiB，给字段和封装留余量。

上传、下载及 claim 的预检查解密共用最多 2 个在途载荷名额，分配大缓冲区前取得，处理结束或中止才释放，下载则持有至响应结束。建议上传总超时 60 秒、claim 及下载总超时 120 秒；满额在扣次数前返回 503 和重试提示。单进程内预留上传配额，计算实际文件、临时文件和进行中预留，另查真实磁盘余量；磁盘写入错误仍必须处理。上线压测实测内存峰值，不能只以文件大小估算。

文件使用独立 Buffer 版 AES-256-GCM：复用现有 `ENCRYPTION_KEY`，严格校验 32 字节十六进制密钥；每文件随机 12 字节 nonce、16 字节 tag，AAD 绑定固定版本前缀和分享 ID。只把密文字节写文件，nonce/tag 放数据库，不调用现有 UTF-8 字符串加密函数，不做 Base64 文件内容。[现有加密实现](https://github.com/dnslin/paste/blob/7350235794ec6e4a664aa35812ab5f83a5aff695/src/lib/crypto.ts)

10 MiB 上限允许整文件有界认证解密；必须等 `decipher.final()` 成功才发送任何明文字节。失败返回错误，不能先流出未认证明文。该设计不支持端到端加密；现有密钥文件与数据同卷，也不防整卷连同密钥被窃。[Node 24 认证解密说明](https://nodejs.org/docs/latest-v24.x/api/crypto.html#deciphersetauthtagbuffer-encoding)

### 落盘和恢复

在持久化卷内设私有文件目录与临时子目录，随机服务端存储名，碰撞时重新生成且禁止覆盖既有对象；目录 0700、文件 0600。原文件名只用于展示和下载名，去除路径片段、控制字符及 CR/LF，限制长度，绝不拼接为实际路径。

上传顺序：取得名额与配额 → 有界读取并加密 → 独占创建临时密文文件、写完并同步 → 同一文件系统原子 rename 并同步目录 → 一个事务插入 `pastes/files` → 返回成功。数据库失败则删除新文件；删除失败留待清理。提交前崩溃最多留下不可访问的孤儿文件，不能留下可领取的半成品。网络断开不承诺上传接口幂等，界面先查管理员列表，不能自动重传造成重复分享。

同一服务在启动时及周期清理，不增加独立 worker。启动接流量前扫描临时文件、无数据库引用文件；运行中仅处理超过上传超时加余量、且不在活动集合内的孤儿文件。清理文件先在事务内标记 `deleting`，阻断领取和新请求，再 unlink，成功或 ENOENT 后事务删除文件分享的 `pastes/files/download_grants` 及密码失败记录；其他删除失败保留状态、记录错误并重试。

过期和撤销可立即进入清理；次数耗尽须等最后一个凭证到期。清理延迟不会延长访问权限。文件删除不能称为物理安全擦除，备份遵守同样的保留规则；原文本过期后管理端仍可查看的行为保持不变。

### 下载响应

每次请求检查凭证、分享期限和 `ready` 状态；有界读入密文、认证解密后，在发响应前再次校验权限。仅返回 `application/octet-stream`、安全编码的 `Content-Disposition: attachment`、`nosniff`、`Cache-Control: private, no-store` 和准确的 `Content-Length`。文件页用 `Referrer-Policy: no-referrer`，不开跨域下载。文件页及元数据、verify、claim 的成功和失败响应也必须 `no-store`，禁止框架缓存或静态生成泄露授权结果。

前端用带 Authorization 的 fetch 获取 Blob，再触发保存，结束后释放对象 URL。v1 忽略 Range，返回完整 200，不返回 206，设置 `Accept-Ranges: none`；断线重试从头下载。同一有效凭证可以重试，服务器不能判断操作系统是否保存成功。[MDN Range 语义](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Range)

## 五 界面和上线边界

沿用深色、琥珀色主按钮和现有卡片间距。已登录管理员在创建区选择“文本 / 文件”；文件选择支持键盘、单文件拖放、移除和换选，展示大小限制、真实上传进度及“服务器处理中”。只有服务器成功返回才显示可复制分享链接。次数文案改为“允许领取下载的次数”，不称“下载成功次数”。[现有设计规范](https://github.com/dnslin/paste/blob/7350235794ec6e4a664aa35812ab5f83a5aff695/docs/ui-design-system.md)

接收页先显示密码门禁，验证后展示名称、大小、有效期及“下载文件”。旁注“领取后扣一次；15 分钟内可重试，分享过期即失效。文件可能有害”。领取、下载、保存准备、失败重试各有明确状态，禁止连点发新领取；剩余次数为零但当前凭证有效时仍提供重试。错误使用文字说明和可读焦点提示，不仅变色。

上线前必须通过真实容器测试：当前 Nginx 上限为 4m，仅文件上传路由提高至建议 11m；其它路由保持原限制。文件目录须挂在现有持久化卷。入口脚本目前先 chown、再以 root 迁移、最后降权，可能出现新建 SQLite 文件归属与运行用户不一致，需验证数据库、WAL 和文件目录均可写，不能仅凭静态检查认为已正确。[Nginx](https://github.com/dnslin/paste/blob/7350235794ec6e4a664aa35812ab5f83a5aff695/nginx.conf) · [容器入口](https://github.com/dnslin/paste/blob/7350235794ec6e4a664aa35812ab5f83a5aff695/docker-entrypoint.sh)

所有新入口保持 HTTPS、服务端权限检查和限流；不记录密码、凭证及文件内容。上传隔离、随机存储名、大小限制和权限控制参考 [OWASP 文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)，本方案不声称实现了其中全部文件检测措施。

## 六 验收与实施顺序

必须覆盖以下风险，而非只测正常上传下载：

1. 旧数据库迁移后原文本 URL、创建、密码、次数及管理员查看行为全部通过回归
2. 未登录上传、跨站上传被拒绝；请求未认证时不先读取大文件
3. 超过限制、伪造长度、chunked、多个文件和异常字段均被限制，正常边界大小可上传
4. 恶意文件名、HTML、SVG、双扩展名不能改变路径、注入响应头或内联执行
5. 有密码文件在页面源码、预取和未授权 API 中不泄露元数据；错误密码不扣次数，锁定有效
6. 剩余一次时不同键并发领取，只成功一次；失败事务不生成凭证也不扣次数
7. 同键并发及提交后响应丢失，最多扣一次；刷新复用凭证，不能跨分享或到期再用同键领取
8. 次数耗尽后旧凭证可重试；分享过期或撤销后旧凭证的新请求均被拒绝
9. HEAD、Range、直接猜测路径均不能绕过授权；GET 重试不额外扣次数
10. 密文、nonce、tag 被篡改或文件缺失时不输出明文；领取前发现损坏不扣次数
11. 磁盘满、数据库失败、写盘或 rename 前后崩溃可恢复，半文件不可公开，孤儿可清理
12. 清理与领取、下载并发不误删有效授权；unlink 失败可重试，已获准响应可完成
13. 超额并发、慢上传和慢下载有界；真实 Docker 重启保留文件、密钥、数据库及可写权限
14. 桌面与手机浏览器验证上传、密码、下载保存及重试；取消或失败不显示“已保存”

按三步实施，每步通过测试再继续：

1. 兼容与存储：确认产品参数；添加迁移、类型分支、加密与私有落盘补偿；完成旧文本回归和故障测试
2. 访问与生命周期：实现校验、原子领取、幂等重试、鉴权下载和清理；通过并发、过期、损坏与权限测试
3. 界面与发布：接入现有设计，配置代理和持久化，执行真实浏览器、容器及容量验收后启用文件入口

本轮不顺带重构文本体系。只有明确需要更大文件、匿名上传或多实例部署时，再重新评估存储、流式认证和资源协调方式。
