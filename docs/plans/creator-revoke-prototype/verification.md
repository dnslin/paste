# 创建者主动撤销原型验证

日期：2026-10-21。环境：Node 24.18.1、pnpm 11.19.0、Chromium。

分支：`codex/creator-revoke-prototype`，基于 `main@de83988`。本轮只新增功能方案、独立原型路由、原型组件和测试。没有修改正式创建、管理、读取或下载接口，没有部署。

## 体验

[打开本机交互原型](http://127.0.0.1:3104/prototype/creator-revoke)

1. 切换文本或文件，查看分别展示的分享链接和私人管理链接。
2. 点击“进入管理页”→“撤销分享”，可以取消或确认。
3. 切换到“接收者页面”，查看撤销后的失效结果。
4. 管理页的“演示状态”可选择过期、次数用尽、无效管理链接和加载失败。“下次撤销失败”用于体验失败和重试。
5. “重置演示”恢复初始状态。复制得到的是原型预览地址，不是真实分享凭证。

原型从创建成功后的结果卡片开始，不模拟真实上传、文本提交或创建时的自动复制。所有状态仅在当前页面内存中保留，刷新重置；不能用它验证真正的管理权限、跨设备撤销或磁盘清理。

## 浏览器实测

以下检查使用最终 standalone 构建产物，加载后确认没有开发工具入口。记录见 [browser-checks.json](./browser-checks.json)。

- 文本和文件两种创建结果分别复制分享／管理演示地址。剪贴板调用被测试替身记录，没有改动系统剪贴板。
- 管理页不出现内容领取操作。确认默认聚焦“继续分享”；Escape 后焦点回到“撤销分享”。
- 文本撤销成功后聚焦成功标题；接收页失效且没有领取操作；返回管理页显示统一失效提示。
- 文件撤销失败时保留明确错误，重试成功；随后接收页失效，返回管理页不再声称可以长期识别撤销原因。
- 已过期／次数用尽时不提供撤销，也不错误显示仍有三次机会；无效管理链接不展示文件名；加载失败后可恢复。
- 拒绝复制时显示可恢复的失败提示。键盘可以完成进入管理、打开确认、Tab 选择确认及撤销成功。
- 文件创建结果在 320/768/1024/1440px 下均无页面横向溢出，也无链接和控件越界。320×900px 下确认框完整位于视口内。
- 减少动态效果偏好下复核现有全局样式对确认框的缩放和位移处理，实际计算值见浏览器记录。
- 流程记录中的业务 `/api/` 请求为 0；捕获的页面错误和未处理 Promise 错误为 0。这些结果只证明模拟流程，不能代替真实后端验收。

## 独立复审

方案复审发现“先暴露管理入口、后新增管理页”的实施顺序问题，已经调整为先完成管理页，再接入创建结果。

原型复审发现取消确认后焦点没有返回入口的问题，已经修复，并补充取消、Escape 和成功标题的行为断言。最终复审没有未解决的实质问题。

测试有效性实验：短暂反转接收者的失效判断，原型测试变为 7 失败／6 通过；在 finally 中逐字节还原后，13 项全部通过。实验没有保留任何改动。
