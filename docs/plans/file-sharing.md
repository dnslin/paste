在现有文本分享旁增加“文件”选项。一次分享一个小文件，生成一个接收链接。接收者可以输入密码并下载，文件不在网页内预览，也不解压、转换或执行。

## 2. 现状与沿用范围

- `src/lib/db/schema.ts` 的 `pastes` 保存加密文本及访问规则。`password_attempts` 保存密码失败次数。
- `src/lib/paste.ts` 在短 SQLite 事务内重新检查状态、解密并消费一次查看机会。错误密码和解密失败不消费次数。
- `GET /api/pastes/:id` 仅返回元数据。受次数限制的文本不会在页面 GET 中预先下发。文件沿用“GET 不领取，用户显式操作才领取”的规则。
- 文本到期或次数用完后停止公开访问，数据仍留在后台。文件新增空间回收要求，不能直接套用文本的保留行为。
- 当前部署为一个 Next.js Node 24 容器、SQLite WAL 和一个持久化 `paste_data` 卷。只有 Nginx 入口对外开放，并覆盖客户端传入的 IP 头。
- `nginx.conf` 当前请求体上限是 `4m`。正式文件接口需要单独调整，不能只修改前端提示或应用校验。
- UI 沿用当前实现的深色背景、Geist、琥珀色主按钮、Logo、网格背景及约 700px 的主内容区域。设计文档中的旧示例不覆盖当前已验证的可访问性和减少动态效果规则。

本轮原型不修改以上生产行为。正式实现时只提取文本和文件都实际使用的访问规则，不顺带重构整个项目。

## 3. 用户流程与文案

### 创建者

1. 在“文本 / 文件”中选择文件。
2. 点击选择文件，或拖入一个文件。显示文件名、大小、移除操作和限制说明。
3. 设置有效期、可选密码和下载机会次数。
4. 点击“上传并创建链接”。上传期间显示进度和取消操作。
5. 成功后显示分享链接、到期时间和次数规则。复制失败时保留可选择的链接并提供重试。

失败不清空所选文件或配置。重试须由用户主动触发。取消时中止请求并清理尚未提交的上传，界面不展示成功链接；如果服务端已提交而响应没有送达，仍可能存在一个等待到期的分享，不能承诺取消一定撤回已完成的创建。上传进度达到 100% 只代表请求体发送完成，仍显示“正在完成分享”，直到服务端返回创建成功。

### 接收者

打开链接只显示文件卡片、大小、到期时间、剩余下载机会和密码输入，不自动下载。文件名可能含私人信息；建议有密码时先显示“受密码保护的文件”，验证后才公开真实文件名和详细信息，最终披露范围待确认。

主要操作为“下载文件”。错误密码、验证锁定、文件已过期、次数用完和服务错误各有明确反馈。用词统一为“下载机会”，并提示：“服务器开始发送完整文件时计为一次；网络中断也可能消耗一次机会。”

下载响应成功仅能说明浏览器已收到文件数据，不能证明用户已保存到磁盘。页面不显示“已安全保存”或“成功下载次数”。

## 4. 数据与模块边界

### 数据库保存元数据，文件系统保存密文

新增具体的 `file_shares` 表，保存分享 ID、原始展示文件名、服务端生成的存储键、净大小、声明类型、密码哈希、到期时间、剩余下载机会、创建时间、AES-GCM 的 IV 和认证标签，以及必要的待删除状态。文件内容作为二进制密文保存到持久化私有目录，例如 `/app/data/files/`；上传中的临时密文放在同一卷内的临时目录。

原始文件名只用于界面和下载名称，不用于磁盘路径。存储键由服务端生成。目录不放进 `public/`，不配置 Nginx 静态访问，也不向客户端返回实际存储路径。文件净字节大小由服务端计算，不相信浏览器报送的大小或 MIME 类型。

不把 Base64 塞入现有正文，不把附件伪装成文本，不增加大文件 BLOB。密文、认证标签和元数据的关联必须完整；文件不存在或校验失败时返回可诊断错误。

`Share` 是文本与文件共同的领域名称，不要求把现有 `pastes` 表、API 和所有组件改名。保留现有文本表，增加文件表，是本轮最小的增量实现。将来是否合表不属于本方案。

密码失败记录需要能区分文本和文件。正式实现可以将 `password_attempts.paste_id` 一次迁移为 `share_id` 并增加具体的 `share_kind`（`text` / `file`）；保留已有文本记录，不维护新旧字段双写。身份键同时包含类型、分享 ID 和可信入口 IP，避免两种分享互相覆盖尝试记录。

### 建议模块

| 边界 | 职责 |
| --- | --- |
| `src/lib/share-access.ts` | 共用状态判断、密码尝试与锁定规则；不处理二进制文件或 HTTP 响应 |
| 现有 `src/lib/paste.ts` | 保留文本读取与文本事务内的次数更新，改为调用共用规则 |
| `src/lib/file-share.ts` | 文件创建、下载领取、短事务内复查状态和扣次数 |
| `src/lib/file-storage.ts` | 私有路径、临时写入、二进制 AES-GCM 加解密、重命名和删除；使用现有 Node 能力 |
| 文件 API 路由 | 请求体限制、参数校验、调用业务函数、返回 JSON 或附件响应 |
| `src/components/file-share/` | 文件选择、上传状态、接收卡片；复用现有基础组件，不修改 `src/components/ui/*` |
| 清理脚本与后台管理 | 回收失效文件、重试失败删除、显示占用和删除状态 |

## 5. 拟议接口

以下是正式实现提案；原型不调用这些接口。JSON 沿用现有 `success()` / `error()` 结构，成功下载例外，直接返回二进制附件。

| 接口 | 行为 |
| --- | --- |
| `POST /api/files` | `multipart/form-data`；一个 `file`、可选 `password`、`expiresIn`（分钟）、`downloadLimit`。创建成功返回 201，包含 `id`、接收页 `url`、`expiresAt` 和规则摘要 |
| `GET /api/files/:id` | 仅返回公开元数据、状态、是否需要密码和剩余机会；不读取文件正文，不扣次数 |
| `POST /api/files/:id/download` | JSON `{ password?: string }`；校验访问权限、完整解密校验、原子领取后返回附件；密码不放在 URL |
| `GET /f/:id` | 接收页面；不预取下载接口，不消费次数 |
| `GET /api/admin/files` | 管理员分页查看文件元数据、占用和删除状态 |
| `DELETE /api/admin/files/:id` | 先停止新领取，再删除密文和对应尝试记录；物理删除失败时保留待删除记录并明确返回未完成 |

错误至少区分：400 参数或密码错误、401 上传/管理身份不满足、404 不存在或不可领取、413 请求或文件超限、429 请求或并发限额、507 存储额度不足、500 文件读写或完整性错误。入口直接返回的 413 也应被上传界面识别，不能假设所有失败都带 JSON。

下载响应包含 `Content-Type: application/octet-stream`、安全编码的 `Content-Disposition: attachment`（含中文文件名的 `filename*`）、`X-Content-Type-Options: nosniff`、`Cache-Control: no-store`、完整文件的 `Content-Length`。拒绝 Range 请求，不接受 GET、HEAD、预览爬虫或重定向令牌来消费下载机会。`attachment` 的用途是下载提示；`nosniff` 禁止浏览器按内容猜测类型，两者均不构成病毒检测。[MDN Content-Disposition](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Disposition)、[MDN X-Content-Type-Options](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Content-Type-Options)

## 6. 上传、容量和并发

限制必须覆盖单文件、整个请求、正在上传的临时占用、已失效但尚未删除的文件、并发请求和下载带宽。单文件 10 MiB 不等于服务总空间受控。

| 资源 | 待评审的起始值 | 执行位置 |
| --- | --- | --- |
| 文件净大小 | 10 MiB | 浏览器提前提示；应用以实际文件字节计数为准 |
| 整个上传请求 | 11 MiB | Nginx 文件路由和应用读取请求流的硬上限；不依赖 `Content-Length` |
| 文件总空间 | 1 GiB | 包括密文、临时文件、待删除文件与并发预留；与文本 DB/备份分开核算 |
| 磁盘空闲余量 | 至少 100 MiB | 保留给 SQLite WAL、密钥与正常运行；实际部署需按卷容量调整 |
| 同时上传 | 全实例 2 个 | 在读取和解析请求体前取得名额，失败或取消时释放 |
| 同时下载准备/发送 | 全实例 4 个 | 覆盖读取、完整解密和响应体生命周期，结束或取消时释放 |
| 上传频率 | 起始建议每可信来源 3 次/分钟 | 独立于现有文本创建额度；匿名模式不能只依赖 IP |
| 下载频率 | 起始建议每可信来源 10 次/分钟 | 与分享剩余机会分开；限制重复下载占用 |

上述资源数值已作为第一版默认值实现，不是目标服务器的容量承诺。上线前仍需根据实际内存、磁盘与带宽测量。首版采用已确认的匿名上传、允许类型及总空间/来源频率限制，不收集身份或增加账号系统。

第一版小文件可采用有硬上限的请求流读取，再使用现有 Web `FormData` 能力解析，不先调用无界 `request.formData()`。多个文件、重复配置字段、额外大字段和实际超过上限的分块传输都拒绝。只有一个文件字段合法；没有文件时拒绝，已选择的零字节文件可以分享，两者不能混为一谈。

通过总请求上限和并发名额限制解析期内存。应实测 multipart、Buffer 加解密和响应持有期间的内存复制，不把“4 × 10 MiB”当作进程内存峰值。若该方案达不到部署内存预算，再选择成熟的流式 multipart 库；目前不预先增加依赖。

开始上传时为其预留最大占用，结束后按实际字节结算。不能由两个并发请求各自读取相同的剩余空间后同时超额写入。单实例内的名额/预留足够；重启后以数据库与磁盘盘点重建，不引入多实例分布式锁。Nginx 请求缓冲产生的临时空间也要计入宿主资源预算，或对文件上传路由关闭请求体缓冲。

## 7. 一次下载的准确含义

第一版以“服务器批准并开始返回一个完整文件”为一次机会，不以 GET 打开接收页、密码验证次数或浏览器保存完成作为计数。

1. 先检查状态、密码和限流，取得下载名额。
2. 从私有目录读取有上限的完整密文，解密到内存，完成 AES-GCM 认证标签校验。校验完成前不向客户端发送任何文件明文字节。
3. 在短 SQLite 事务内重新检查到期、撤销、锁定和当前剩余次数；有次数限制时原子减一。文件 IO 和 bcrypt 不放进数据库事务。
4. 只有领取成功才构造附件响应。领取失败立即丢弃内存明文。
5. 最后一次领取成功后，后续请求不可再领取；已获准的响应可以发送手中经过校验的 Buffer，后台可开始删除磁盘密文。

密码错误、过期、完整性校验失败、额度不足，以及并发竞争中没有领取成功的请求都不扣次数。最后一次机会遇到多个并发下载，只能有一个获得文件。

事务提交后到网络完成之间无法与浏览器磁盘保存做一个原子操作。连接中断、页面关闭或浏览器拒绝保存可能已经耗费一次。第一版不自动返还机会，也不提供重试凭证；界面在下载前告知此语义。服务错误在扣数之前发生则不耗费。完整缓冲下载降低半个坏文件外泄的风险，但不承诺网络一定送达。

## 8. 文件与数据库之间的失败处理

SQLite 事务不能同时提交文件系统写入。采用短步骤和可重复清理，避免构造一套通用事务框架。

### 创建

先在私有临时目录写密文并完成写入，再在同一卷内重命名到正式随机存储键，最后插入可领取的元数据。只有这三步完成才返回分享链接。

| 失败点 | 用户可见结果与恢复 |
| --- | --- |
| 超限、取消、解析失败或写入失败 | 创建失败，不返回分享链接；关闭文件句柄、删除临时文件并释放预留 |
| 文件完成，数据库插入失败 | 创建失败；立即删除正式文件；删除再失败则记录日志，由孤立文件扫描回收 |
| 进程在重命名后、DB 插入前退出 | 启动清理发现没有元数据的正式文件，在没有活跃上传的启动阶段回收 |
| 创建已完成，成功响应丢失 | 分享可能已存在直到到期；界面说明重试会新建分享，不伪称上传一定没有完成 |
| DB 有记录而文件丢失或被破坏 | 下载返回错误且不扣次数；记录具体分享 ID 和存储错误供管理员处理 |

### 停止访问与物理删除

到期、机会用完或管理员删除时立即禁止**新的领取**。已经获得内存文件的响应不会被事后收回。物理删除是从文件系统移除密文，两者不是同一时刻。

建议到期或次数用完后回收文件，不像文本一样长期保留正文。清理作业每 5 分钟运行并在启动时补跑；这是待确认的清理目标，停机或 IO 失败会延迟。后台显示“已停止访问，等待删除”或“删除失败，等待重试”，只在 `unlink` 成功或文件已经不存在后显示“文件已删除”。保留最小待删除元数据直到清理完成，随后删除记录与密码尝试记录，不建立长期历史档案。

管理员删除沿用同一流程：先记为待删除，让访问规则立即拒绝，再删除文件，最后清理元数据。再次执行可以继续完成。文件已经不存在是正常清理状态；权限不足、磁盘 IO 等其他失败保留日志并重试，不能当作成功吞掉。

运行中只清理失效记录指向的文件，孤立文件全面扫描在启动阶段执行，避免误删尚未写入 DB 的活跃上传。临时密文在取消时即时清理，崩溃遗留在重启时清理。有限状态只服务实际的跨存储恢复，不增加上传会话、分布式任务或多阶段发布机制。

删除普通文件不等于对 SSD、安全快照或备份中的数据作可证明擦除。文件、数据库和持久化密钥需要一致的备份/恢复策略；若备份保留文件，须另行确认保留时长。界面不承诺“立即彻底销毁”或“无法恢复”。[Bitwarden Send Lifespan](https://bitwarden.com/help/send-lifespan/) 也分别描述到期停止访问与删除生命周期；本方案只借鉴该产品区分，不照搬其额度或加密架构。

## 9. 准入与安全边界

真实边界是匿名用户可以写入服务器磁盘、接收者可能下载恶意文件，以及拥有服务端密钥的运营者能够读取内容。私有存储、固定资源上限、访问规则和下载响应服务这些具体边界。

- 允许扩展名、MIME 和文件签名检查只能约束业务接收范围。浏览器 MIME 可伪造，ZIP 也可能携带恶意内容。第一版没有病毒扫描，不显示“已扫描”“无病毒”或“安全文件”。
- 不解析、预览、执行或解压文件，降低服务端处理不可信内容的范围；这不使接收者打开文件自动安全。
- 复用现有服务端 AES-256-GCM 和持久化密钥机制。服务器在上传/下载时接触明文，这属于服务端加密存储，**不是端到端加密**。正式公网使用还需要 HTTPS。
- 链接持有者可按规则下载；密码提供额外访问条件。密码不负责派生文件加密密钥，不能对管理员保密。
- 上传接口必须在读取大请求体之前执行已确认的准入与限额。不因“文本已经匿名开放”就默认文件也匿名开放。若选择公开匿名上传，需明确容量、滥用处理入口和运营责任，再启用真实写入。
- 继续仅信任覆盖 IP 头的入口代理。直接运行时沿用共享限额，不能让客户端自报 IP 获得新额度。

上述私有路径、服务端存储键、大小与访问限制对应 [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) 的存储、命名、准入和容量建议。没有扫描或审核能力时不宣称已完整实施该清单。

## 10. 原型范围与页面

原型固定在 **`/prototype/file-sharing`**，明确标注“交互原型：文件仅保留在当前浏览器，本演示不会上传到服务器”。现有主页、API、数据库、业务组件和 UI 基础库不变。本轮具体交互与视觉验收以 [文件分享交互原型](./file-sharing-prototype.md) 为准，以下保留与正式功能的衔接范围。

原型包含四个可切换的视图：创建分享（文本 / 文件）、分享成功弹窗、接收文件页、简洁后台文件管理预览。接收页演示密码、下载、过期和次数耗尽状态；后台演示元数据、空间摘要、删除确认与删除状态。

复用当前 `Button`、`Input`、`Select`、`Dialog`、Logo、Geist、琥珀色和网格样式。桌面内容宽度与当前约 700px 区域保持一致，手机单列，控件关联中文标签，键盘可操作，状态变化通过可访问提示表达。进度用于说明模拟状态，不添加循环装饰或页面交错动画；减少动态模式下禁用位移、缩放。

浏览器选择和拖拽真实本地 `File`，但上传进度、成功链接、失败、取消、密码校验、次数和后台清单均为模拟状态。下载只使用当前浏览器中的文件或内置示例 Markdown，通过浏览器 Blob 下载；离开页面时释放对象 URL。不使用 localStorage/IndexedDB 持久化文件，也不向任意网络发送文件内容。演示链接不代表可跨浏览器或跨设备分享。

原型中的删除只移除演示状态，不能用来证明服务端删除；上传 100%、模拟存储占用、到期时间同样标明演示含义。原型的目标是评审信息层级、选项、提示和操作流程，不验证加密、限流或物理清理。

## 11. 交付阶段与外部可观察验收

| 阶段 | 交付与进入下一阶段的条件 |
| --- | --- |
| A：方案 + 原型 | 本提案和独立 UI 原型；不依赖公网准入/额度决定，不连接真实后端 |
| B：最小真实闭环 | 确认准入和额度后，完成数据库迁移、私有加密写入、元数据接收页、显式下载与删除；先在隔离测试目录验收 |
| C：部署与容量验证 | 验证 Nginx/应用请求上限、总空间和并发名额、取消/崩溃恢复、定时清理、备份与错误日志后，再启用生产文件分享 |

原型验收场景：

1. 在窄屏和桌面分别选择、拖入、移除文件；无文件、多个文件、超 10 MiB 均有清晰反馈。
2. 修改密码、有效期和次数，模拟上传；失败保留选择，重试可继续，取消不出现成功链接。
3. 成功弹窗复制被拒绝时可选择链接并重试；重新创建恢复空状态。
4. 接收页必须由用户点击下载；错误密码、过期、机会用完可切换演示；本地文件下载内容与原文件一致。
5. 后台删除有确认，删除当前演示分享后接收页停止下载，数量和模拟占用同步变化。提示清楚说明只删除演示记录；等待清理/删除失败等服务端状态留待真实闭环验证。
6. 全程不调用文件 API，不写数据库，现有首页行为不变；键盘路径、焦点和减少动态模式可用。

真实功能验收场景：

1. 10 MiB 边界文件可创建，超 1 字节被拒绝；缺少/伪造 `Content-Length`、multipart 大字段和多个文件仍受总请求上限约束。
2. 连续 GET、HEAD、分享预览和接收页刷新不扣次数，也不下发密文或明文文件；只有显式 POST 下载消费机会。
3. 1 次机会面对多个同时下载，仅一个返回完整文件；错误密码、锁定、过期和文件损坏不消费机会。
4. 篡改密文或认证标签时不发送任何明文字节；下载的二进制、中文文件名、空格文件名和附件头正确。
5. 超限额、并发满、磁盘写入失败、数据库插入失败、请求取消和进程中断都没有可访问的半成品；重启能清理孤立文件。
6. 到期或末次领取后立即拒绝新请求；清理后磁盘空间实际释放。删除失败时后台保持待删除状态并能重试。
7. 下载连接中断可能消耗一次，界面文案与观察一致；不自动返还或偷偷重复下载。
8. 绕过入口直连和伪造转发头不能增加额度；公开匿名开关及最终准入策略实际生效。
9. 文本创建、查看、密码锁定、最后一次领取和后台管理回归通过；迁移保留既有文本分享。
10. 实际执行相关 Vitest、类型检查、ESLint、生产构建和真实浏览器流程，另做 Docker/Nginx 上传与故障恢复验证；记录真实命令和未验证范围。

## 12. 已确认决定与运维边界

已确认按原型实现：单文件 10 MiB、默认一天/最长七天、可选密码、下载次数，以及密码前隐藏文件名称和大小。用户另行确认匿名上传，仅允许文本/PDF/常见图片/ZIP。

总空间、磁盘余量、并发、频率和五分钟清理使用本方案默认值。备份保留期由部署方设置，不能将在线文件到期等同于备份已删除。Docker/Nginx 和目标服务器容量仍需部署阶段验证。
